## Open defect

`sst.main._amend` (and `_verify`) call `conn.rollback()` only when `audit.ReasonRequired` is raised. If the `UPDATE assay_results` statement fails after the audit rows have been inserted, the request returns 500 but the shared connection keeps the open transaction (`get_conn` does not roll back on exception), so the next request's `commit()` persists `update` audit rows describing an amendment that never took effect (result still `0.155`). This conflicts with SOP-DI-004 §6(d) (no partial audit) and URS-002 accuracy. Reproduced by step 8. Application code is out of scope for this workstream; raised for disposition under CHG-4127.
