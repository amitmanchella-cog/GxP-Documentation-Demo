| ID | Requirement | GxP impact | Source |
|---|---|---|---|
| URS-001 | The system shall apply record controls (audit-trail events, reason-for-change rule, deletion mode, rounding mode, retention) from the active regime configuration file; regime behaviour shall not be hard-coded. | High | SOP-CSV-010 §5; shared platform decision CC-2025-009 |
| URS-002 | Every create, modify or delete of an assay result — including amendment of the measured value (URS-010) and second-person verification of an amendment (URS-011) — shall write an audit-trail entry with user ID, UTC timestamp, record ID, field, old value, new value and reason, in the same transaction as the change; a modification that changes several fields shall record each changed field. | High | SOP-DI-004 §4.1, §4.4; 21 CFR 11.10(e); CHG-4127 |
| URS-003 | Modification (including amendment and amendment verification) or deletion of an assay result shall be rejected, leaving the record unchanged, unless a reason for change of at least the configured minimum length is supplied; deletion shall be a soft delete that preserves the record. | High | SOP-DI-004 §4.2–4.3, §5.1; CHG-4127 |
| URS-004 | The system shall compute the reportable value by rounding the measured value once, to the precision of the specification limit, with exact decimal arithmetic and the regime's rounding mode (half-up for GMP), and shall set the OOS flag by comparing the reportable value with the limit. Users shall not be able to set or clear the OOS flag. | High | SOP-QC-021 §4–5 |
| URS-005 | Users shall be able to list studies, list and filter samples by study and status, and view a sample with its results, specification, OOS status, analyst, instrument and test time. | Medium | QC stability workflow |
| URS-006 | The result page shall show the full record history (audit trail) for that result; a system-wide audit-trail view shall be available. | High | SOP-DI-004 §4.6 |
| URS-007 | Every action shall be attributed to the authenticated user supplied by the site SSO proxy. | High | SOP-DI-004 §3 (Attributable) |
| URS-008 | A JSON API shall allow result creation, retrieval, amendment of the measured value (URS-010), verification of a pending amendment (URS-011), soft deletion and audit retrieval for integration with the chromatography data system. | High | Interface spec IF-CDS-02; CHG-4127 |
| URS-009 | Timestamps shall be system-generated in UTC and not user-editable. | High | SOP-DI-004 §3 (Contemporaneous) |
| URS-010 | Provisioned users with an authorised analyst or supervisor role (QC Analyst, Senior QC Analyst, QC Supervisor) shall be able to amend the measured value of a non-deleted assay result through the application only (result page or API), with a mandatory reason for change. The measured value shall be validated as a decimal number; an unchanged value shall be rejected. The original value shall be preserved in the audit trail and shown in the record history. The reportable value and OOS flag shall be recomputed per URS-004 and the result status set to `Amended`. | High | SOP-DI-004 §5.1–5.2; SOP-QC-021 §6.2; CHG-4127 |
| URS-011 | An amendment that changes the OOS conclusion shall not be reportable until it is verified by a QC Supervisor other than the amending analyst; until then the result shall carry status `Amended - pending verification` and no further amendment shall be accepted. Verification shall be attributable, audited and require a reason for change. | High | SOP-DI-004 §5.3; `config/regimes/gmp.yaml` `second_person_verification_on_oos_change: true`; CHG-4127 |
