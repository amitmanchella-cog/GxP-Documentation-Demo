# URS-SST — User Requirements Specification, Stability Sample Tracker

*Last approved revision: 3.4 (effective 2025-05-19; author T. Brennan, reviewed A. Diallo 2025-05-12, approved H. Lindqvist 2025-05-16).*

| ID | Requirement | GxP impact | Source |
|---|---|---|---|
| URS-001 | The system shall apply record controls (audit-trail events, reason-for-change rule, deletion mode, rounding mode, retention) from the active regime configuration file; regime behaviour shall not be hard-coded. | High | SOP-CSV-010 §5; shared platform decision CC-2025-009 |
| URS-002 | Every create, modify (including amendment and amendment verification) or delete of an assay result shall write an audit-trail entry with user ID, UTC timestamp, record ID, field, old value, new value and reason. An amendment shall write one entry for each field whose value changes. | High | SOP-DI-004 §4.1, §4.5; 21 CFR 11.10(e) |
| URS-003 | Modification (including amendment and amendment verification) or deletion of an assay result shall be rejected, leaving the record and audit trail unchanged, unless a reason for change of at least the configured minimum length is supplied; deletion shall be a soft delete that preserves the record; a deleted result shall not be amendable. | High | SOP-DI-004 §4.2–4.3, §5.1 |
| URS-004 | The system shall compute the reportable value by rounding the measured value once, to the precision of the specification limit, with exact decimal arithmetic and the regime's rounding mode (half-up for GMP), and shall set the OOS flag by comparing the reportable value with the limit. Users shall not be able to set or clear the OOS flag. | High | SOP-QC-021 §4–5 |
| URS-005 | Users shall be able to list studies, list and filter samples by study and status, and view a sample with its results, specification, OOS status, analyst, instrument and test time. | Medium | QC stability workflow |
| URS-006 | The result page shall show the full record history (audit trail) for that result, including each amendment and verification with old and new values per field; it shall offer amendment (with a mandatory reason field) only for results that are not deleted, and shall show when a result is pending second-person verification. Deleted results remain viewable with their history. A system-wide audit-trail view shall be available. | High | SOP-DI-004 §4.6, §5.3 |
| URS-007 | Every action, including amendment and amendment verification, shall be attributed to the authenticated user supplied by the site SSO proxy; write actions shall be refused for users who are not provisioned and active in SST. | High | SOP-DI-004 §3 (Attributable), §5.1 |
| URS-008 | A JSON API shall allow result creation, retrieval, amendment, amendment verification, soft deletion and audit retrieval for integration with the chromatography data system; invalid input shall be refused with a client error, not a server error. | High | Interface spec IF-CDS-02; SOP-QC-021 §6.1 |
| URS-009 | Timestamps shall be system-generated in UTC and not user-editable. | High | SOP-DI-004 §3 (Contemporaneous) |
| URS-010 | An authorised user (QC Analyst, Senior QC Analyst or QC Supervisor) shall be able to amend the measured value of an assay result that has not been deleted. The amendment shall be rejected unless a reason for change of at least the configured minimum length is supplied, and rejected when the new value is not a decimal number or is equal to the current value. The system shall recompute the reportable value and OOS flag from the amended value with the same exact-decimal rounding and specification comparison as URS-004. Every field that changes (measured value, reportable value, OOS flag, status) shall be audited with user, UTC timestamp, old value, new value and reason, so the original values remain retrievable from the record history. | High | SOP-DI-004 §3 (Original, Attributable), §4.1–4.2, §5.1–5.2; SOP-QC-021 §4–5; CHG-4127 |
| URS-011 | When an amendment changes the OOS conclusion and the active regime requires second-person verification, the result shall be held in status `Pending verification` and shall not be treated as reportable until a QC Supervisor who is not the user who made the amendment verifies it with a reason for change. The verification shall be audited. | High | SOP-DI-004 §5.3; SOP-QC-021 §6.2; CHG-4127 |
