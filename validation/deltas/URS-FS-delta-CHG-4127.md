| ID | New / Changed | Text | GxP impact | Source |

| URS-010 | New | An authorised user (QC Analyst, Senior QC Analyst or QC Supervisor) shall be able to amend the measured value of an assay result that has not been deleted. The amendment shall be rejected unless a reason for change of at least the configured minimum length is supplied, and rejected when the new value is not a decimal number or is equal to the current value. The system shall recompute the reportable value and OOS flag from the amended value with the same exact-decimal rounding and specification comparison as URS-004. Every field that changes (measured value, reportable value, OOS flag, status) shall be audited with user, UTC timestamp, old value, new value and reason, so the original values remain retrievable from the record history. | High | SOP-DI-004 §3 (Original, Attributable), §4.1–4.2, §5.1–5.2; SOP-QC-021 §4–5; CR #2; PR #6 F1–F6, F9, F12 |

The verification shall be audited. | High | SOP-DI-004 §5.3; SOP-QC-021 §6.2; `gmp.yaml` `second_person_verification_on_oos_change: true`; PR #6 F7 |

## Open items flagged for QA / Change Owner
| # | Item | Effect on this delta |
|---|---|---|
| O1 | **Code gap against URS-011, reproduced at `805496c`.** A second amendment of a result in `Pending verification` that keeps the new OOS conclusion sets status to `Amended` with no verification: `_amend` compares the new OOS flag with the already-amended flag, not the last verified one. Seeded NMT 0.15 result: amend 0.155 → 0.154 gives `Pending verification`; amend again → 0.153 gives `Amended`, verify never called. | FS-009 describes the code as it is. URS-011 is not met until `_amend` keeps `Pending verification` (or blocks amendment) while a result is pending, and a regression test is added. |
| O2 | F11: `gmp.yaml` lists `amendment_verification` under `e_signature.required_for`; SST has no e-signature. FS-010 verification is an audit entry, not a 21 CFR 11.50/11.200 signature. | QA decision needed: sign in the QMS or raise a follow-up CR. |
| O3 | Reportability relies on the `status` value. Home and sample-list OOS counts use `oos` regardless of status; SST has no release function. | URS-011 "not treated as reportable" is met only through the status shown to users; confirm this is acceptable. |
| O4 | `_verify` checks state (409) before role (403), so an unauthorised caller can learn that a result is pending. | Informational; behaviour documented in FS-010. |
