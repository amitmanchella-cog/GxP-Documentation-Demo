| ID | Function | Implements | Design |
|---|---|---|---|
| FS-001 | `sst.regimes.load_regime()` reads `config/app.yaml` → `active_regime` and `config/regimes/<code>.yaml` into an immutable `Regime` object; `Regime.requires_audit(action)` / `requires_reason(action)` are the only decision points for record controls. | URS-001 | `sst/regimes.py` |
| FS-002 | `sst.audit.record()` inserts one `audit_trail` row (ts, actor, entity, entity_id, action, field, old_value, new_value, reason) for each mutation; timestamps via `utcnow()` (UTC, ms, `Z`). All write paths in `sst/main.py` (`api_create_result`, `api_delete_result`, `_amend`, `_verify`) call it before commit in the same transaction; `_amend` writes one `update` row per changed field among `measured_value`, `reportable_value`, `oos`, `status`, and `_verify` writes one `update` row on `status`. | URS-002, URS-009, URS-010, URS-011 | `sst/audit.py`, `sst/main.py` |
| FS-003 | `record()` raises `ReasonRequired` when `requires_reason(action)` and `len(reason) < reason_min_length`; `api_delete_result`, `_amend` and `_verify` map it to HTTP 422 after `conn.rollback()`, before the result row is updated. `DELETE /api/results/{id}` sets `deleted=1, status='Deleted'`; `_get_result()` excludes deleted rows, so API retrieval, amendment and verification of a deleted result return 404 (the result page uses `include_deleted=True`, FS-006). | URS-003 | `sst/audit.py`, `sst/main.py::api_delete_result`, `::_amend`, `::_verify` |
| FS-004 | `sst.rounding.evaluate(measured, lower, upper, mode, inclusive)` → `(reportable, oos)` is the only reportable-value / OOS path; it is called by `api_create_result` and `_amend` with `regime.results.rounding` and `regime.results.limit_inclusive`. `decimal_places()` derives precision from the limit text (the larger of the lower and upper limit); `reportable_value()` uses `Decimal(str(x)).quantize()` with `ROUND_HALF_UP` (or `ROUND_HALF_EVEN` for regimes that configure it); `is_oos()` compares inclusively unless the regime sets `limit_inclusive: false`. Stored columns: `measured_value`, `reportable_value`, `oos`. | URS-004, URS-010 | `sst/rounding.py`, `sst/main.py::_amend` |
| FS-005 | HTML views `/`, `/samples`, `/samples/{id}` (Jinja2 templates) with per-row OOS highlighting and result counts. | URS-005 | `sst/main.py`, `sst/templates/` |
| FS-006 | `/results/{id}` (`result_detail`, `_get_result(include_deleted=True)`) shows the result and its `audit_trail` rows; `result.html` shows the amend form (`measured_value` with the decimal pattern, `reason` with `minlength = reason_min_length`, both required) only for non-deleted results and, while status is `Pending verification`, a notice and the verification form (browser checks are convenience only; server checks are FS-009/FS-010). `/audit` lists the latest N entries; `/api/results/{id}/audit` returns them as JSON. No update or delete route exists for `audit_trail`. | URS-006 | `sst/main.py`, `sst/templates/result.html` |
| FS-007 | `current_user()` reads `X-User` set by the SSO proxy (fallback `SST_USER` for local dev); `provisioned_user()` returns the active `users` row or raises HTTP 403 and is called by `api_create_result`, `api_delete_result`, `_amend` and `_verify`. The user is stored as `analyst` on created results and `actor` on audit rows; amendment does not change `analyst`, the amending and verifying users are the audit `actor`. | URS-007 | `sst/main.py::current_user`, `::provisioned_user` |
| FS-008 | `POST /api/results` (201) validates `measured_value` against `MEASURED_VALUE_PATTERN`, computes FS-004, writes the result and the `create` audit row; `GET /api/results/{id}`; `DELETE /api/results/{id}` (FS-003); `PATCH /api/results/{id}` (FS-009); `POST /api/results/{id}/verify` (FS-010). Request-body validation failures return 422. | URS-008 | `sst/main.py` |
| FS-009 | `sst.main._amend(conn, regime, actor, result_id, measured_value, reason)`: (1) `_get_result()` → 404 if missing or deleted; (2) `provisioned_user()` → 403 if not an active user, 403 if role not in `AMEND_ROLES = {"QC Analyst", "Senior QC Analyst", "QC Supervisor"}`; (3) value must match `MEASURED_VALUE_PATTERN` (`^-?\d+(\.\d+)?$`) → else 422; (4) `Decimal` equal to the current value → 422; (5) `evaluate()` with the regime rounding mode and `limit_inclusive` (FS-004); (6) status `PENDING_VERIFICATION` (`"Pending verification"`) if the OOS flag changes and `regime.records.second_person_verification_on_oos_change` is true, else `"Amended"`; (7) one `audit.record(action="update")` per changed field (`measured_value`, `reportable_value`, `oos`, `status`) with old value, new value and reason; `ReasonRequired` → rollback + 422; (8) `UPDATE assay_results` and commit. Routes: `PATCH /api/results/{id}` (`api_amend_result`, body `AmendIn {measured_value, reason}`, both required) → 200 with the updated result; `POST /results/{id}/amend` (`amend_result_form`, form `measured_value`, `reason`) → 303 to `/results/{id}`. | URS-010, URS-011 | `sst/main.py::_amend`, `::api_amend_result`, `::amend_result_form` |
| FS-010 | `sst.main._verify(conn, regime, actor, result_id, reason)`: (1) `_get_result()` → 404; (2) status ≠ `PENDING_VERIFICATION` → 409; (3) `provisioned_user()` → 403 if not an active user, 403 if role not in `VERIFY_ROLES = {"QC Supervisor"}`; (4) actor equal to `_last_amender()` (actor of the latest `update` audit row on `measured_value`) → 403; (5) `audit.record(action="update", field="status", old="Pending verification", new="Amended", reason)`; `ReasonRequired` → rollback + 422; (6) `UPDATE assay_results SET status='Amended'` and commit. Routes: `POST /api/results/{id}/verify` (`api_verify_result`, body `VerifyIn {reason}`) → 200; `POST /results/{id}/verify` (`verify_result_form`, form `reason`) → 303 to `/results/{id}`. The verification is an attributed audit entry, not an electronic signature. | URS-011 | `sst/main.py::_verify`, `::_last_amender`, `::api_verify_result`, `::verify_result_form` |

Data model: `studies`, `batches`, `storage_conditions`, `specifications` (limits stored as text to preserve precision), `samples`, `assay_results`, `audit_trail`, `users` — see `sst/db.py` (schema version 7). `assay_results.status` values: `Entered` (default), `Reviewed`, `Amended`, `Pending verification`, `Deleted`.
